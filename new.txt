3. 🔴 SqlMigrator نفسه فيه مشكلة تصميم خطيرة

البرنامج يفعل:

var files = Directory.GetFiles(migrPath, "*.sql");
Array.Sort(files);

ثم:

cmd.CommandText = sql;
await cmd.ExecuteNonQueryAsync();

لكن عندك داخل SQL:

GO

وعندك:

:r "../sys/nav.sql"

وهذان ليسا أوامر SQL Server عادية يمكن إرسالها بواسطة SqlCommand.

GO يفهمه SQLCMD/SSMS كـbatch separator، وليس SQL Server engine.

و:r أمر SQLCMD.

لذلك:

SqlMigrator
    ↓
SqlConnection
    ↓
ExecuteNonQuery

لن يكون قادراً على تنفيذ هذه migrations كما هي.

الحل الذي أوصي به

نحتاج Migration Engine حقيقي:

MigrationRunner
│
├── Discover migrations
├── Validate sequence
├── Track applied migrations
├── Parse GO batches
├── Resolve :r includes
├── Execute transactionally
├── Record checksum
└── Rollback/failure handling

ومع جدول:

dbo.__SchemaMigrations

مثلاً:

MigrationId
Name
AppliedAt
Checksum
ExecutionTimeMs
Success

ولا نعيد تشغيل migration تم تطبيقها.
